Targets and endpoints

Only a platform admin manages connections.

Targets

What an assessment can be about: the system, and each component its AI card lists (models, rule engines, the data it is trained on, ...). Every evaluation picks one as its target, and every result says which. A component the latest card no longer lists stays, marked, with its results. Components are added on the AI card, under Qualification.

Endpoints

How a target is reached over the network, when an assessment calls it: at most one endpoint per target. A test that calls a system reaches the endpoint of its evaluation's target. A key is stored encrypted for this project only and is never shown again.

Allowed internal hosts

A connection may call any public address. An internal one (a private network, the Docker host, a machine on your LAN) is refused unless it is listed here, as a host or host:port. Changes apply to the next call, with no restart. The services of this deployment, loopback (the platform itself) and cloud metadata addresses are never allowed here.
