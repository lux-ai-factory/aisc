System and components

What an assessment can be about: the system, and each component its AI card lists (models, rule engines, the data it is trained on, ...). Every run names the one it tested, and every result says which. A component the latest AI card no longer lists stays, marked, with its results. Components are added on the AI card, in step 1, Qualify. A test that calls the system or a component reaches it through its connection, shown on its row; next to it, the installed tests that can assess it.

Connections without a target

Connections made before every connection had to name what it reaches. A test that names one directly can still use it; link it to the system or a component that has no connection yet so that tests picking that target reach it.

Allowed internal hosts

A connection may call any public address. An internal one (a private network, the Docker host, a machine on your LAN) is refused unless it is listed here, as a host or host:port. Changes apply to the next call, with no restart. The services of this deployment, loopback (the platform itself) and cloud metadata addresses are never allowed here.
