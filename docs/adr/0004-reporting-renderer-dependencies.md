# 0004. Reporting renderer: Python-native PDF/Word in the backend, no browser

**Status:** accepted
**Invariant:** I8 — new production dependencies decided (not waived)
**Owner:** AISC project owner (reporting workstream, epic E5)
**Date:** 2026-11-17

## Context

ADR 0003 (decision 7) requires the unified app to preserve the pilot's real PDF/Word reporting and to
inventory the renderer's production dependencies and runtime costs before choosing a deployment
approach. **Any new top-level production dependency requires its own I8 ADR** — this one.

### Inventory of the pilot renderer (REP-00)

The pilot splits reporting in two: `apps/report-composer` (FastAPI) assembles a layout from ordered
**blocks**, and `apps/report-generator` (a separate FastAPI service, pinned submodule
`aisc-report-generator@6f86121`) renders HTML and PDF. The generator's `pyproject.toml` and
`Dockerfile` at that pin declare:

| Need | Pilot package | Runtime cost |
| --- | --- | --- |
| HTML → PDF | `weasyprint>=70` | system **libcairo2, libpango1.0, libpangocairo, libharfbuzz, libgdk-pixbuf, libffi, libxml2, libxslt1.1**, fonts (dejavu/inter/liberation/roboto) |
| DOCX | `python-docx>=1.1` | pure Python |
| SVG logos → PDF | `cairosvg>=2.7` (+ `defusedxml`) | libcairo (already present) |
| Images | `pillow>=12.3` | wheels |
| SVG parsing | `lxml>=5` | wheels |
| Templates | `jinja2>=3.1` | pure Python |
| Per-tool report renderers | `aisc-report-plugin-*` (langbite, mlareject, promptfoo, strongreject) | one plugin package per tool, discovered via the `aisc_report.tools` entry point |

**The pilot renderer has no Chromium/browser dependency.** PDF comes from WeasyPrint (HTML/CSS), not a
headless browser. The unified app already talks to such a service through one seam,
`services/report_service.generate` (POST `REPORT_SERVICE_URL`), which until now fell back to a
deterministic **HTML** summary when no service was configured — so a `pdf` request could return HTML.

## Decision

1. **No browser.** Do not introduce Chromium/Playwright for reporting.
2. **Render in-process, Python-native.** The backend renders the real document itself with
   `reportlab` (PDF) and `python-docx` (Word); the block registry
   (`services/report_blocks`) and the frozen-snapshot document model
   (`services/report_render`) carry the pilot's block vocabulary (cover, key figures, control
   objectives, test results, evidence coverage, charts, …) and the layout order. `reportlab` and
   `python-docx` are the only two new top-level production dependencies.
3. **Keep the service seam.** `services/report_service.generate` still prefers an external renderer when
   `REPORT_SERVICE_URL` is set (a deployment may run the pilot's WeasyPrint generator), but it now
   **degrades to the in-process renderer** instead of to HTML, so a `pdf`/`docx` request is always a
   real PDF/Word document. This is what makes the I8 choice reversible: the seam is unchanged.
4. **Defer the heavy fidelity features.** WeasyPrint's HTML/CSS template fidelity, `cairosvg` SVG
   logos and the per-tool plugin renderers are **not** ported yet; the unified renderer draws the
   same information with its own layout. They are recorded as open work in
   [`../refactor-deviations.md`](../refactor-deviations.md), not silently dropped.

## Consequences

- **Cost:** two new top-level production dependencies (`reportlab`, `python-docx`) in
  `apps/backend/pyproject.toml` + `uv.lock`. No system packages, no container, no browser, no new
  service in the default deployment. `reportlab` is a large wheel but pure-Python-installable; it does
  not need libcairo/pango, so the backend image is unchanged.
- **Feature parity:** the *information* of every pilot block is retained; the pilot's exact
  HTML/CSS template styling is not. A report generated by the in-process renderer and one generated
  by a configured WeasyPrint service are both real PDFs but not byte-identical.
- **Guard:** none added. `tests/architecture` is unchanged (5 passed, 3 xfailed, 0 failed); this ADR
  does not move a boundary or add a datastore.
- **Removal condition:** if report styling fidelity becomes a release requirement, port the pilot's
  `report_renderer/` (Jinja templates + WeasyPrint + `cairosvg`) as the in-process renderer and drop
  `reportlab` — the `report_service.generate` seam and the frozen-snapshot model already allow it.
  Revisit when the per-tool plugin renderers are wanted (they need the `aisc-report-plugin-*` packages
  and the `aisc_report.tools` entry point), or when a deployment sets `REPORT_SERVICE_URL` and the
  in-process path is no longer exercised.
