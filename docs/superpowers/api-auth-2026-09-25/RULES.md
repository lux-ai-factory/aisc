# Rules for every work package (read first, with 01-inventory.md)

## Goal (user, 2026-09-25)
"secure the API with auth and do the same for the APIs of all other apps (except catalogue and engine)".
Out of scope: catalogue (apps/catalogue), engine (apps/backend, apps/webapp, apps/eval), devpi ("will be on
a host"). The per-project LLM keys feature is already done (docs/superpowers/pipeline-2026-09-24-llm-keys).

## Approved design
- Browser-facing APIs (control-objectives, qualification-web): every route requires the Keycloak token
  check (shared/identity, as the pages do) AND project membership; writes need editor (or platform
  admin, as today's rules say). Only exceptions: the public objectives catalogue (/objectives,
  /api/control-objectives*, /api/macro-requirements, /api/config, /static/*) and /health. An object
  addressed by id is checked against ITS OWN project; the project never comes from the browser.
  Path matching must not be bypassable by a root-path prefix (e.g. /control-objectives/p/...).
- Service-only APIs (qualification-agents, qualification-ontology, qualification-prefill,
  qualification-llm, qualification-pdf, controls-pdf): a service token PER CALLER, sent in a header,
  compared in constant time, fail closed (503 when the token var is unset, 401 when wrong), /health
  stays open. Model it on the platform's per-system tokens (platform/platform_service/app.py
  resolve_llm, SYSTEM_TOKENS): distinct secrets per caller edge, generated by scripts/secrets.sh (append
  only, never rewrite existing values), wired in docker-compose.development.yml as `${NAME:?run
  scripts/secrets.sh first}`, commented in env.development and env.staging.
- The card agent must be able to GET and PUT qualification-web /api/qualifications/{id}/extracted with a
  service credential (today it gets 404 without a user token): accept a dedicated agent token on
  exactly those two routes, and check the qualification's own project exists.
- control-objectives must forward the user's token to platform/qualification-web the way the gateway
  delivers it (X-Auth-Request-Access-Token, see shared/identity headers.py), not only Authorization.

## Safety
- Branch feat/unified-modules in every repo; local commits by explicit path; NEVER push.
- NEVER run docker compose up/down/build/restart against the running stack (project `aisc`); never write
  to live databases. The orchestrator deploys.
- apps/qualification has UNCOMMITTED work from another session (forms, prefill, ontology, renderer,
  prisma migration 20260925090000_forms_are_data). Never revert, stash or commit it. If you must edit a
  file it also changed, stage only your own hunks (build the staged blob from HEAD plus your change,
  `git update-index --cacheinfo`), and verify your commit alone in a clean `git worktree` (symlink
  node_modules) before reporting.
- homepage/project.html has an uncommitted user edit: do not commit it.
- Tests use throwaway databases only (recipe: docs/superpowers/pipeline-2026-09-24-llm-keys/02-tests.md
  section 3); ALWAYS set PLATFORM_TEST_DATABASE_URL / module DB vars; remove containers afterwards.
- TDD: failing tests first, then code. Never weaken existing tests; update a test only where the
  approved design changes the behaviour it pins, and say so.
- Prose without em dashes. Write your notes to <wp>-notes.md in this directory and commit it.
