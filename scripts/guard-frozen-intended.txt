# G4 (scripts/guard-frozen.sh): the files feat/deployment-modes changes in the webapp on top of
# upstream origin/master, one per line, each with the area of the change and why. Every other
# webapp file must be byte-identical to its base. The backend and the worker (apps/backend,
# apps/eval) are ours to change and are not listed.
#
#   base <repo> <commit>             origin/master of the repo, the base of feat/deployment-modes
#   <repo> <path> <labels>: <reason> a file feat/deployment-modes adds or changes on purpose
#
# Labels, comma-separated, name the area of the change:
#   modes         the configurator mode next to upstream's standalone one: project, session, install
#                 target and pages per mode
#   reports       the /report links removed: the AISC stack never serves /report, the report is the
#                 report composer's
#   wording       the start button says Launch Evaluation
#   project       each tab works on its own project: installs and saved selections never take another's
#   errors        failed runs and refused actions shown with their reason
#   dependencies  shipped dependencies above their vulnerable ranges
#   docs          the README
#   secrets       a plugin form's key kept as a project secret: a test only, the form is upstream's
#   helpers       models a test uses as tools (judge, attacker...) are the project's helper models, picked in
#                 the run form; the AI System offers no LLM components
#   identity      a plugin is told apart by its package and its name: two packages may ship a plugin of the
#                 same name (a copy of a test), and selecting or running one never takes the other
#   names         a plugin configuration is named when it is saved, shown by name in Config History and the
#                 run form; Config History keeps the current configuration while the form is edited
#   runs          a run is named at launch or afterwards, shown by its name, and can be stopped from the
#                 progress bar
#   versions      a project may hold several versions of a test's package, one on; the one off shows no card
#   retire        a dataset deleted while evaluations used it is retired, not removed: it leaves the test data
#                 list and the run forms, Show retired lists it with Restore
#   launch        a relaunch keeps the last run's helper models (its judge); a refused launch says the engine's
#                 reason once; with no connection for a helper role the run form sends the person to Connectivity;
#                 a launch is sent once: the button is off while it is sent and each click carries its own key;
#                 a test that calls its target while no target of the AI card has a connection is greyed out on
#                 the launch page and never ticked, the engine saying why (GET /plugins/launch-blockers)
#   testdata      Delete on test data asks first; a refused add or edit, or a file the engine could not store, is
#                 said with the engine's reason and the dialog stays open
#   filetypes     a dataset or model file picker offers only the extensions the engine takes for that type
#   images        the image installs exactly what package-lock.json pins (npm ci) and serves as nginx's
#                 unprivileged user
#
# Derived with `git diff --name-only <base> HEAD` in apps/webapp.
# A new change goes in here with its reason, in the same commit as the gitlink that brings it.
